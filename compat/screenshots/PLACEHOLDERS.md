# 截图占位

下面的 PNG 文件名与 README 中的图片引用一致。仓库里先放同名说明文件；实拍后替换为真实图像（建议宽度约 720–1080px 的界面截图）。

拍摄环境建议：SillyTavern 1.19.0 + 已打本目录补丁 + 已启用「断因」扩展。使用中文界面。提示条应出现在对应助手消息正文下方。

| 文件名 | 应拍摄的内容 | 怎么拍 |
| --- | --- | --- |
| `truncated-length.png` | 长度上限截断提示 | Chat Completion，把 Max Response Length 设得很小，让回复在句子中间断开。提示应类似「回复被截断了」，并带「继续生成」。 |
| `content-filter.png` | 内容过滤提示 | 使提供方返回 `content_filter` / `SAFETY` / `PROHIBITED_CONTENT`（不要用恐吓性标题）。提示应说明可能是提供方策略，即使 ST 安全选项为关。不要出现「继续生成」也可以（此类 `action` 为空）。 |
| `thinking-quota.png` | 思考额度用尽、可见回复很短或为空 | Google 思考模型（或经 OpenRouter 的同类模型），开启 include thoughts，上限中等。可见正文很短，但思考很长。提示应说明思考占用了额度，建议提高上限或换不带思考的模型，并带「继续生成」。 |
| `unknown-fallback.png` | 读不到结束原因时的兜底 | 在扩展会调用 `classify(null, …)` 的情况下，或提供方未返回原因时。提示应平静说明「无法判断是写完了、被截断还是被过滤」，并建议必要时继续或提高上限。 |
| `normal-stop-no-hint.png`（可选） | 正常结束不应出现提示条 | 一次完整、自然结束的回复（`stop`）。截图用于对比：消息旁没有断因提示。 |

请勿在截图中包含 API 密钥、完整系统提示或可识别的个人信息。
